# Database migrations

EmergentSH uses Alembic for every production schema change. Runtime schema
creation is disabled by default: `AUTO_CREATE_SCHEMA=true` is supported only
for disposable local/test databases.

## New environments

Set `DATABASE_URL` and run:

```powershell
python -m alembic upgrade head
```

Current head is `b724e18a09f1`, which adds durable worker leases, retry counts,
target metadata, and the persisted mock/live execution selection to pipeline
jobs. Multiple replicas may poll safely because claiming is atomic.

The backend container performs this command before it starts Uvicorn.

## Existing legacy environments

Older deployments were created with SQLAlchemy `create_all` and have no
Alembic version table. Do **not** run the initial migration blindly against
one of those databases: it establishes the full schema for a new database.

After taking and verifying a backup, inspect the schema against the revision
and, only when it matches, establish the baseline without DDL:

```powershell
python -m alembic stamp 9936aa792817
```

If the legacy database is missing a table or column, write a targeted forward
migration for that exact state instead of stamping it. This makes the required
operator decision explicit and prevents startup from silently altering a
production database.

## Creating a new revision

```powershell
python -m alembic revision --autogenerate -m "describe the change"
python -m alembic upgrade head
```

Review autogenerated DDL before applying it. Test both a clean database and
the applicable upgrade path before deploying.
